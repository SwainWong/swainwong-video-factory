## 子 Agent Harness

当前工作流为 1 个主 Agent＋12 个子 Agent 职责。主 Agent 派单前读取[内部岗位方法与 Harness 索引](../roles/INDEX.md)，把岗位编号、对应 `METHOD.md` / `HARNESS.md`、同版输入、适用规则 ID、产物和验收证据写进任务包。每个子 Agent 只读取自己的内部角色模块和任务相关共享合同；总 Harness 负责跨岗位依赖和全流程关口。内部角色模块不带 `SKILL.md` 或 `agents/openai.yaml`，不得作为顶层 Skill 暴露给用户。

前三类规定行为，第四类规定如何确认行为真正发生。

## 从审片反馈持续打磨

审片页面提交会保存原评论、视频身份、所选时间段和提取证据。Agent 实际接收后，必须按[反馈沉淀合同](../references/harness-feedback.md)逐条解析并写回结果：优先引用已有规则；新的可复用经验进入对应目录的 `candidates/`。

候选只供审阅，不参与 MUST／禁令执行；独立审核和具体条款及范围确认后才进入 `confirmed/` 并链接到分类索引。项目返修、候选状态和成片验收状态分别报告。原评论选择“仅返修，不沉淀”时不得创建候选。

## 主 Agent 的使用顺序

1. 识别任务范围：新片／重编、局部返修、纯音频、规范讨论。只有新片与重编执行完整制作入口；局部工作只检查适用项，并说明验收范围。
2. 读取 MUST、MUST NOT 和验收表，选出当前阶段适用规则；依据规则链接读取详细合同。涉及选型时读取 SHOULD。
3. 派单附上：输入版本与哈希、适用规则 ID、应交付产物、验收证据、依赖和未决事项。主 Agent 管理协调，生产和独立审核身份分开；用户指定独立 Codex 制作对话时，主对话不得直接写脚本、字幕、工程或渲染产物，只能修工作流、派单、核证据和门禁放行。
4. 收到结果先核文件和证据，再记录状态。报告说“完成”本身不能证明完成。
5. `editing-first-full-cut` 先执行 [First Full Cut 合同](../references/first-full-cut.md)：脚本必须可生产，并先通过[定稿式口播合同](../references/editorial-style-and-subtitles.md)的机器预检与独立编导判断；整片时长和时间线必须完整，临时项必须显式登记；最终素材、动画、SFX、BGM和混音不作为这一关的前置。
6. `editing-final` 必须同时提交候选文件、`swainwong.subtitle-phrase-gate.v1`、`swainwong.final-visual-gate-input.v2` 和 `swainwong.final-visual-gate.v2`；逐单元语义字段及片头／中段／片尾字幕最终像素证明属于硬输入。随后三份 G3 结构化独立审核绑定同一哈希，`candidate-internal-gate` 才汇总 [candidate AV gate](../references/candidate-av-gate.md)。素材政策、短语级单一字幕、口播节奏、SFX可辨、BGM可闻、章节导航、来源质量、同源唯一性任一未通过都不能生成 `owner-review-ready`。
7. 失败只阻断受影响依赖；继续已授权且不依赖缺口的工作。缺少用户决定时集中提出最小问题，已有授权和选择不重复询问。
8. 输入或输出变化后标记受影响检查过期，重新核对；保留旧记录。交付逐项列技术、视觉、听审和用户确认状态。

执行顺序：入口锁定 → 研究与可生产脚本 → 编导／事实 G1 → 粗分镜 → 尽快形成完整 First Full Cut → G2 整片诊断 → 在整片上横向替换素材、配音、动画/SFX、BGM/混音 → 候选＋最终视觉机器门禁 → G3 三审 → candidate-internal-gate → owner-review-ready → 用户审核／交付反馈。高风险小样只可并行验证具体未知项，不得阻塞整片粗剪。

## 规则如何维护

- 本期明确选择优先于已确认长期偏好，长期偏好优先于 skill 默认；仍须遵守更高层指令与真实授权范围。
- “一定”只对适用范围内成立。例如第三方 B-roll 的同源去重不能直接套到授权主持 A-roll；纯音频任务不需要视频平台表单。
- 每条规则有稳定 ID、触发条件、动作或禁令、检查证据、失败处理、原文依据。阈值与详细配方保留在原合同，避免两处各改一版。
- 推荐不得悄悄升级为必须；一次成功案例不得直接成为永久偏好；新禁令必须有明确用户要求或已核实失败依据。
- 发生同级规则冲突时列出具体条款与适用范围。无法依据明确选择解决的，只暂停受冲突影响的部分，不自行挑较方便的一条。
- 当前 `SKILL.md` 保留简短路由和必要约束，并链接总 Harness、岗位索引和详细合同；原 `references/`、`scripts/`、`assets/`、`agents/` 继续保留。四类目录是总流程规则分类，不限制整个 skill 的目录数量。

## Harness 的实现边界

当前成果包含 Markdown 规则、提交取证、分析写回和带确认依据的规则纳入工具。文件存在、字段完整、哈希一致和技术参数适合程序检查；声画语义、动作可信、表演自然度需要实际看／听及独立审核；用户确认必须来自真实输入。三者不可互相代替。

后续自动化应把各条检查标为“已有并实测／待接入／人工或独立审核”，运行第四目录中的行为场景，再逐步接上自动检查。不能因目录和清单已建好就宣称制作稳定性已验证。
