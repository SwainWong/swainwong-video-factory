# 案例：关系驱动的财经/商业讲解动画

来源案例：[BV1FCps68EGf](https://www.bilibili.com/video/BV1FCps68EGf/)（小Lin说《史上最大现金收购案 富二代如何正确拼爹》）。这是 `reference_only` 的私下研究，不是素材授权，也不是要求模仿创作者的完整视觉身份。

## 什么时候读取

当脚本包含多方人物/公司关系、收购/融资/报价比较、新闻证据、资金流、权力结构、来源截图或需要用第三方画面解释机制时读取。若只是普通口播、旅行实拍或纸艺动作，不必加载整篇。

## 可迁移的核心规则

1. 把每个口播意群先标成 `身份 / 证据 / 关系 / 比较 / 计算 / 机制 / 情绪反差 / 结论` 中的一个主任务。
2. 画面按“对象→关系→数值/状态→结论”揭示；不要先给满图让观众猜正在讲哪一部分。
3. 同一对象使用稳定 ID、颜色和锚点。关系变化靠箭头、连线、移动、重排或失活，而不是突然换一套无关联图形。
4. 复杂图表分阶段，每阶段只新增一个主要信息点；终态至少保留完整阅读时间。
5. 常用硬切、暗化、局部放大和节点状态变化即可完成信息交接；转场本身不能代替解释。
6. 主持人小圆窗是可选的叙事锚点：只在持续口播或需要保留解释者时使用，独立视频层、静音，不能遮挡图表和字幕。

## 第三方视频选择

先写 `claimRole` 再选片：`identity`（建立身份）、`evidence`（交易/声明/文件）、`mechanism`（表现流向或动作）、`contrast`（情绪或权力反差）、`return`（回收前面对象）。每个片段只承担一个主任务，优先选择最短但动作完整的连续镜头；同主题但不推进论点的 B-roll 删除或换为静态证据。

素材台账至少记录 `source、in/out、creator/title、rights_status、audio_mode、used_claim、return_cue`。公开可见不等于可发布；本案例的画面和片中第三方素材不得直接进入成片。

## ChatCut / OpenFilm 映射

- ChatCut：A-roll、第三方视频、证据截图、主持人圆窗和 MG 分轨；文本/数字/颜色/节点/箭头作为可编辑属性；用 composed timeline 检查入口、揭示、定格、退场。不要把参考片截图当作背景图或 MG 模板。
- OpenFilm：用 `film.html` 排序独立 video/image/page；用 SVG/Canvas 画关系和图表，DOM/CSS 画可编辑文字；所有状态从当前时间计算，支持随机寻帧和回拖；数据与来源放旁车配置。
- 两者都要把字幕作为独立字幕系统或独立层，第三方原声是否保留单独记录；平台预览、渲染、MP4 存在、解码和创作验收分开报告。
