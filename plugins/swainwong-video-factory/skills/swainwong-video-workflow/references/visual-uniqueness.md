# 画面去重与口播对应

A-roll范围例外：以下同源唯一性与整镜模板去重针对被引用证据/B-roll和讲解内容，不禁止授权主持的同源不同有效句段或固定全屏/分屏/PiP容器复用。不得循环同一口型/动作、冻结或重放讲话凑时；其下B-roll和图表继续受本文约束。台账标记source_role=presenter_a_roll并按[A-roll合同](a-roll.md)登记take与句子ID，引用采访不能改名主持绕过规则。

## 硬性规则与适用范围

用于同一成片的分镜、选材、图表设计、剪辑及最终审片。第三方视频/图片重复使用、DataMagic或其他一般相同整镜数据表格/动画效果重复套用，均为Critical；第二次就不通过。用户要求的素材占比、节奏、时长与本规则必须同时满足，不能靠重复素材填时长或凑占比。本规则不禁止不同项目使用同一配方库。

### 第三方视频和图片

- 每张原始图片只能有一次连续展示；切走后再切回即为重复。图片做章节卡后在另一处作背景，也算二次使用。
- 每个第三方原始视频只安排一个连续选段。不同时间码、拆成多个文件、不同上传者转载、视频截图，都不能另算新素材。不得循环、倒放或重复同一动作填时长。
- 裁切、缩放、推拉、镜像、调色、遮罩、模糊、换字幕、改文件名或重新编码，不改变原始素材身份。
- 一个镜头内为完整动作/原声/阅读保留的连续展示算一次；换旁白或章节后重新启动同一画面，不得包装成“连续性”。
- 素材不够时继续寻找不同原始照片/视频，或为当前意群设计全新的动画。不能以“有新观点”“有意回扣”“免费素材少”为由重复使用。

### D01 章节包装的有限复用

[D01 主体遮挡章节标题](explainer-motion/foreground-depth-title.md)属于本次明确授权的章节包装：可在不同真实口播章节开头复用同一层级配方及基础代码，但每处须有独立章节观点、不同原始素材、符合口播的标题及可读停留。按语气选择入场并避免机械连用；无需为保留包装一致性强造另一种布局。相同源素材的背景与抠像在同一连续镜头内算一个 visual_unit，切走再用仍算重复。此例外不允许重复第三方原片／原图、表格、数据图、一般整镜内容模板，不授予纯素材超过 5 秒的延时例外。记录 packaging_role=chapter_opener、recipe_id=D01、章节与原始素材身份。

### H01 开头预告的有限包装复用

用户选择 [H01 爆点预告式开头](explainer-motion/highlight-hook-opening.md)时，同一段预告内的多个爆点可共享 D01 大字在后、主体在前的层级、字体与基础动画代码；各爆点须有独立语义、对应主体与阅读窗口，按 opening_mode=H01、packaging_role=opening_hook、hook_id 登记，不伪报正文新章节。该例外不允许重复第三方原片／原图、证据截图、完整镜头或一般数据图；预告与正文的素材须一并去重。它不授予纯素材延时或覆盖率例外，也不意味着每片必须采用。

### DataMagic及其他讲解图表/动画

- 除上文 D01 章节包装及 H01 开头包装限定范围外，每个整镜模板或可辨识的动画效果只使用一次；不能把同一双栏表、同一关系图、同一节点布局、同一套入场—高亮—退场过程反复套到不同口播。
- 同一数据表或图表不能切走后重放，也不能仅换标题、数值、人物名、颜色、位置、时长、配方ID或组件名宣称是新动画。不同ID但实际同构的效果仍判重复。
- 选择顺序：本句讲什么关系/变化 → 观众要看懂什么 → 选择尚未使用、适合该关系的视觉结构 → 设计对应的信息揭示顺序。既检查唯一性，也检查口播与画面是否一致。
- 回扣与总结用新的视觉表达概括已得出的结论，不重新播放之前的整张图表或动画。
- 允许同一图表在一个连续镜头中逐步展开、更新或保持可读状态；这是一段完整解释，不能复制到后面的意群。
- 可以共享字体、配色、基础绘图/插值代码和角色身份；不能共享后只换数据，输出观众看起来相同的整镜结构与动作。固定Logo、字幕槽、来源样式、常驻分段进度条是持续导航/品牌层，不计重复主画面，也不能替主画面提供所谓“新内容”。

## 分镜与素材台账

一镜一行，至少记录：

| 字段 | 用途 |
|---|---|
| scene_id / script_id / claim_id | 本镜对应的原句、论点和独立视觉任务 |
| origin_id / original_url / original_path | 原始照片或原始视频身份；转载与派生版本归到同一身份 |
| visual_unit_id / source_in_out / timeline_in_out | 本次唯一使用的位置；派生裁切沿用原始身份 |
| recipe_id / visual_structure / motion_sequence | 动画来源、整镜布局/图表结构、揭示与运动顺序；自制动画同样登记 |
| first_use_scene / duplicate_of / check_status | 首次使用镜头、疑似重复对象、PASS/REVISE/UNRESOLVED及依据 |
| distinct_visual_reason / narration_match | 与本片其他镜头的实质区别；如何直接表达当前口播 |

原始素材只能对应一次使用；一般整镜效果只能对应一个连续视觉解释单元，D01 章节包装及 H01 开头包装按上述限定范围单列。主画面与小窗/背景均纳入检查，不能靠移到小窗规避去重。

## 检查与放行

1. **分镜锁定前**：按原始素材身份与效果结构分组查重；每个意群已分配独立画面。缺素材或效果时继续补充，不能先标PASS再渲染。
2. **工程检查**：从实际时间轴列出所有素材使用区间与动画实例。文件hash只能识别完全相同文件；还须检查原始URL、源片身份、派生关系和效果结构，防止重新编码、转载、截图或换ID漏检。
3. **成片检查**：按实际镜头起止及关键状态生成联系表，并连续观看复核；把可疑镜头并排比较。画面第一眼须对应当前口播，不能只查文字内容。固定间隔抽帧不足以证明短镜去重。
4. **报告**：分别给出第三方素材重复项、动画效果重复项、口播错配项，列出scene_id与时间码。目标都是0；有重复或未判定项就不授予该阶段PASS。
5. **修复**：替换为新的原始素材，或重做视觉结构与动画；更新台账并复核受影响镜头。不得以已渲染、时长不足、比例达标、风格统一为由保留重复。

技术hash、唯一ID数量和素材总时长不是观感去重通过的证据。实际不能连续看或核对时，记录覆盖缺口，不把数据检查升级为成片视觉验收。
