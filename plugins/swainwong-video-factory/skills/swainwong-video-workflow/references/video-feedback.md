# 视频审片页面与偏好沉淀

## 每次渲染后的交付

适用于 First Full Cut、完整候选与每个返修版。⑧交付岗位在实际视频生成后提供可播放和补充评论的本地页面；主Agent传递页面与反馈，不代替制作或独立审核。页面分为 `internal` 诊断与 `owner` 验收两种受控入口；该动作不增加每版强制等待用户批准的关口，继续遵循本期已确认的人类参与方式。

1. 记录实际输出的绝对路径、SHA-256、时长和可获得的帧率；记录项目身份及已有任务号。OpenFilm工程路径/标识、ChatCut任务标识只在真实可获取时关联，缺失记为未知，不编造成功派单或平台流水号。
2. 启动skill内工具，参数使用实际绝对路径：

   ```bash
   python3 /absolute/path/to/swainwong-video-workflow/scripts/serve_video_review.py --video /absolute/path/video.mp4 --project /absolute/path/project --port 8767 --thread-id ACTUAL_CODEX_THREAD_ID
   ```

   页面模板为`assets/video-review.html`。候选未到 `owner-review-ready` 时使用 `--audience internal`，页面必须醒目标明不能作为用户验收或交付；只有状态机确认同一哈希已通过最终视觉门禁、G3 和 candidate AV gate，才能使用 `--audience owner`。检查服务器实际返回的地址和视频身份，不把端口占用时已有的其他页面当成本次成果。若工具或服务未能启动，说明原因并提供实际视频和现有反馈文件，不宣称页面可用。
3. 通过`open_in_codex`打开实际页面URL，并在交付中同时提供可点击审片页面、视频文件及反馈文件位置。仅在后台启动服务不算已展示；服务器停止后URL不可用，需要按上述命令重新启动。
4. 反馈持久化到`<project>/review-feedback/<sha256>/comments.json`，重新加载后可读取。相同视频身份可以继续评论，重新渲染且哈希改变时建立独立记录，不能覆盖旧评论或静默挪用旧时间码。

## 整轮提交与送达状态

逐条保存是本地草稿。页面汇总本轮待提交反馈，用户查看组织后的完整消息，再点击发送；消息包含实际项目、视频路径与哈希、时码、原始观察、修改建议、偏好候选、评论 ID 和唯一提交号。目标 Codex 对话由启动服务时的真实 `--thread-id` 绑定，网页不能任意改写接收人或调用通用工具。

每轮预览保留不可变的 `submissions/<提交号>/snapshot.json` 和 `message.md`，发送状态另存 `state.json`。预览后评论发生变化必须重新生成预览；已发送或结果未明的评论不能再次混入新提交。

| 状态 | 实际含义 | 页面应如何表达 |
|---|---|---|
| 已保存 | 评论已写入本地项目 | 待提交，不代表 Agent 收到 |
| `preview` | 已生成消息快照 | 可检查文案，不代表尝试发送 |
| 接口不可用 | 当前没有可验证的发送桥 | 说明原因，保留评论与预览，禁止显示发送成功 |
| `sending` | 已启动一次发送尝试 | 等待回执，防止双击与重复提交 |
| `queued` | 官方 Codex 队列已接受，返回队列项 ID | 已提交到制作对话队列；当前工作结束后接收，不代表 Agent 已读取 |
| `sent` | 正式接口返回可核验的接收回执 | 展示提交号和目标对话；仅表示消息送达，不代表已返修 |
| `agent_received` | 目标 Agent 实际收到并确认本提交号 | 已确认接收；后续返修和验收仍分别记录 |
| `failed` | 明确没有发送成功 | 保留本轮快照与错误，修复原因后才重试 |
| `unknown` | 超时、断连或重启导致结果不明 | 先查目标对话和唯一提交号，不能盲目重发 |

连接能力必须实测。只读能力探测成功不等于消息送达；保存、排队、网页显示成功或独立 CLI 完成均不能替代接收回执。发送超时后不得自动重放；重启时尚在 `sending` 的记录按 `unknown` 处理。回执与视频哈希、目标对话、提交号绑定，不能拿另一轮成功替代本轮结果。

## 官方队列：默认提交路径

普通审片网页由本地服务使用官方 `codex queue --thread <绑定对话> --message <本轮完整消息>` 入队。以参数数组启动进程，不拼接 shell；保持既有模型、目录、权限和制作条件，不附加覆盖参数。接口写入既有线程的共享持久队列，不需要创建新线程、`exec resume` 或加载独立制作实例。返回 `Queued message <队列项ID> for thread <线程ID>.` 时须核对线程 ID 并记录回执；仅标 `queued`。

官方队列会等待当前 turn 正常结束，目标线程空闲后处理下一条消息；不要为等消费而让当前 turn 无限等待。已中断、未加载或关闭的目标线程可能继续保留排队项，不能承诺即时唤醒。队列内有记录证明仍在等待；记录消失不单独证明已收到，须由目标 Agent 的实际消息或可核验历史确认。超时或输出无法解析时记 `unknown`，先核对唯一标识，不再次调用 CLI 盲重发。

Agent 实际收到后，按下节核验快照及视频，再通过接收确认工具或本地确认脚本更新 `agent_received`。接收确认应核验当前会话身份、提交号和视频哈希；网页不能自行声称 Agent 已收到。页面中的排队、收到、返修完成、验收通过分别显示。

实现依据为官方 `rust-v0.164.0` 的 `tui/src/session_queue_commands.rs`、`app-server/src/request_processors/thread_queue_processor.rs` 和 `ext/queue/src/service.rs`。本机核验（2026-10-26）已完成普通网页端到端提交：提交号 `132474c3-f520-4aed-81a5-a3b023587aa3`、官方队列项 `01a17655-1dd4-7343-abbd-d3b891f33990` 在目标忙碌 turn 正常结束后进入同一对话；目标 Agent 核验身份及视频哈希后确认 `agent_received`，页面实际显示“Agent 已收到”。本次视频 SHA-256 为 `5267157b19c5b13ec6af6d1c697c8063504246d1c47e963ce0cb0a3a25f5ad2f`；完整回执与页面证据见[技术验证记录](/Users/swainwong/Desktop/video-factory/work/video-review-tool/independent-review.md)。生产使用普通网页和官方 queue，无插件刷新依赖；未使用的实验 MCP 注册已移除。该证据只覆盖本机该版本及该次提交，不代表关闭或中断对话可即时消费，也不代表返修完成或风格偏好获确认。以后每次能力升级都记录本次证据，不能继承旧版测试结果。

## 独立 native pipe 的已知限制

本机核验（2026-10-26）：官方 bundled `codex-app-tools` 独立 MCP 入口可初始化，但 `tools/list` 返回 `Codex app tools pipe closed`。使用应用原装 Node 和入口的同步只读探测，桌面日志记录 `dynamic_app_tools_peer_rejected reason=untrusted-code-signing-identity`（2026-10-26T03:08:47.053Z）；这是该独立进程的身份校验失败，不是评论内容、thread metadata 缺失，也不代表 Codex 没有其他正式提交接口。不得改签、伪装受信进程或直接修改应用数据库绕过；也不可通过另一个 daemon 的 `resume/start` 冒充向当前桌面运行实例发送。官方 `queue` 是独立的受支持机制，按其真实入队和消费证据判断。

## 与四类 Harness 的持续对接

普通网页提供“由 Agent 理解后归类／一定要做／推荐做／一定不能做／验收与失败处理／仅返修不沉淀”。预览时对实际绑定视频提取截图或短片段，随不可变提交保存；自动取证范围与缺口明确列入消息。已发送提交的分析状态从项目文件刷新到页面。

每轮接收后执行[反馈到 Harness 的沉淀合同](harness-feedback.md)：将观察、修复、既有规则匹配、新候选及验证缺口分开；用 `harness_feedback.py record` 写回，持续汇入四类目录。该自动化负责证据和记录，语义理解仍由实际收到反馈的 Agent 执行。

## Agent 接收到提交后的处理合同

1. 以唯一提交号确认收到，读取绑定的不可变快照，核对目标项目及实际视频 SHA-256；重复提交号只更新状态，不重复派单。
2. 按时码查看对应画面或片段；必要时由工具提取证据，不能要求用户重复手工截图。原视频不可用或哈希不匹配时明确指出，不用新版替代旧版证据。
3. 主 Agent 汇总反馈并派给对应专业岗。保留原始观察与评论 ID，专业岗将“具体问题→修改方案→可抽象规则”分开记录；冲突或改变锁定条件的反馈按原有确认规则处理。
4. 修改后由独立审核岗复核受影响镜头，记录处理结果、证据和新版本关联，并重新提供审片页。提交评论、消息送达、返修完成与整片验收是不同状态。
5. 长期偏好候选按下文独立核对和人类确认流程处理，不能因消息已提交就自动改写永久偏好或 Codex 记忆。

## 原生 MCP App：实验备选路径

原生路径将审片页作为 MCP UI 资源交给 Codex 宿主承载；它与普通 localhost 浏览器页是两个入口。本路径作为实验备选，只有实际工具加载、原生页面播放与消息接收验证完成后才能对用户启用。工具通过 `_meta.ui.resourceUri` 关联 `text/html;profile=mcp-app` 资源，评论与快照读写走受限 MCP 工具，用户点击发送时由页面调用标准 `ui/message` 请求宿主向当前对话提交。此路径不从外部进程调用桌面 native pipe，不沿用独立桥的不可用结论，也不能仅凭符合标准就宣称当前 Codex 版本已运行通过。

- **绑定先于发送**：服务固定项目、视频和制作对话；校验宿主实际传来的 MCP 调用元数据。网页自己填写的对话 ID 不构成调用方证明。缺少可验证调用方、对话不匹配或宿主没有 `message.text` 能力时，发送停用；不能把“当前对话”默认为最初制作对话。
- **先留快照，再调宿主**：发送前持久化本轮消息、提交号和 `sending` 状态，再发一次 `ui/message`。明确失败可记录失败；超时、断线、页面关闭或回执保存失败时保留未明状态，先核验再重试。
- **状态分层**：`host_accepted` 仅表示宿主对 `ui/message` 返回成功；`agent_received` 只有目标 Agent 实际读取该提交号、核验视频并确认接收后才能记录。两者都不等于返修完成或整片验收。旧独立桥的 `sent` 与原生宿主回执保留各自提供方，不混淆证据。
- **媒体单独验证**：localhost 视频来源须在资源 `_meta.ui.csp.resourceDomains` 中声明；宿主可进一步限制来源，声明不等于播放成功。真实播放、定位、逐帧/片段评论、消息送达和刷新恢复都需要在原生宿主实测。不要用模拟 host、普通浏览器页面或静态截图替代此证据。
- **注册与刷新**：通过官方本地 MCP 配置注册服务，并核对当前对话实际出现对应工具和原生 UI。CLI 配置写入、stdio 测试通过或 server 启动不等于当前回合完成热加载；需要刷新时明确说明具体 MCP 服务刷新步骤，不擅自重启正在工作的整个应用。

## 评论内容

页面应支持播放、定位、暂停后对单帧添加评论，以及标记开始/结束时间对片段添加评论。保存所评论时的时码；有可靠帧率时可辅助显示帧号，变帧率或浏览器定位精度不足时不伪称精确解码帧。附带的截图属于观察证据，不代替视频动态检查。

评论采用“具体观察→希望怎样修改→可沉淀的通用偏好→适用范围”，不能要求用户每次填完整专业报告；具体观察可单独保存，其余字段按需补充。可包括素材/动画/数据图表/排版/口播/声音/品牌包装等类别，以及问题、喜欢、建议等反馈倾向。

| 具体观察 | 希望怎样修改 | 可沉淀的通用偏好 | 适用范围 |
|---|---|---|---|
| 本镜白底图标又套了一层圆底 | 使用轮廓完整的透明裁片 | 相同画面内避免无语义的重复套底，裁片材质统一 | 本期；或用户显式标为长期候选 |
| 表格在讲到最后一行前就切走 | 按口播逐行揭示并留足阅读时间 | 数据密度与停留时长匹配，当前讲解数据有清晰焦点 | 数据图表镜头 |
| 喜欢这个结尾节奏 | 保留节奏，替换本期Logo与文案 | 结尾配方将节奏与品牌资产分离，资产可替换 | 指定系列或长期候选 |

默认范围是本期。用户可以显式标记“长期偏好候选”，但单次喜欢、通过镜头或保存评论不能自动转换为已确认的永久规则。保留原始评论，Agent提炼的版本与原文分开、可追溯。

## 从反馈到返修或长期规则

- **本期返修**：主Agent按反馈类别派给相关制作岗；制作岗记录改动及新版本，独立审核岗对照实际新输出复核。原评论保留，关联新版本与处理结果；新旧镜头时间变化时重新定位，不机械复制旧时码。
- **偏好提炼**：对应专业岗持续分析反馈；普通本期意见可提炼为待审候选，但不自动生效，显式“仅返修不沉淀”除外。候选写成“适用场景→可执行规则→检查证据”，说明适用的内容类型和例外，不把具体品牌/镜头写成通用默认。
- **独立核对**：审核岗检查是否忠实于原反馈、是否能被观察验证、与已确认规则是否冲突。主Agent汇总报告，不自行签发独立审核结论。
- **确认与使用**：只有用户明确接受该长期规则及范围后，才能写入已确认偏好；尚未确认的保持候选。本期明确选择优先于长期偏好，长期偏好优先于skill默认值。具体案例留项目，获确认的可复用规范才进入风格档案或skill；不因此自动改动Codex记忆文件。

评论状态与成片审核状态分开。修改一个镜头、关闭一条评论或确认一项偏好，均不等于用户批准整片；用户明确给出的整片验收意见单独记录。页面播放、抽帧、ASR、响度检查和评论记录都不能替代连续全速观看及真实听审，继续按[审核门槛](review-gates.md)报告实际覆盖。

## 版本与磁盘

旧视频清理前，保留其哈希、时长、输出版本、任务/平台关联信息、评论与处理记录。需要证明问题的帧或短片段可以保留并记录原时码；按本期磁盘预算只保留必要证据，不默认复制整片或无限保存全部历史媒体。删除原视频后明确标记不可播放状态，不能将旧评论链接到新版假装原证据仍在。人类原始素材与仍被可编辑工程引用的必要素材继续遵循既有保护和清理授权。
