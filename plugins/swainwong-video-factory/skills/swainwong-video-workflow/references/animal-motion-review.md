# 动物动作可信度审查

适用于动物走、跑、跳、飞、落地和攀爬等动作；二维卡通、剪纸和三维均适用。目标是让儿童能相信动物如何动起来，不要求肌肉仿真、完整解剖骨架或固定姿态数量。卡通可以夸张高度、节奏和表情，但必须保留支撑、发力和承重的可读因果。风格认可、轨迹顺滑与动作可信是三个不同判断。

## 五项检查

| 项 | 必须回答的简单问题 | 阻断例子 |
|---|---|---|
| `force_chain` 发力与承重 | 从哪里获得推动？什么时候离开支撑？怎么接住身体？ | 静坐造型整体升空；先离地后蹬腿；落地没有肢体承重 |
| `articulation` 身体姿态 | 躯干与主要肢体是否配合？关节弯曲、伸展和收回是否连续？ | 整体缩放冒充腿伸展；脚一直抱在胸前；关节突变或肢体脱开 |
| `contacts` 接触 | 支撑阶段脚/爪是否留在支撑物上？释放与重接触是否明确？ | 脚滑动但无步伐；脚穿地；停在枝上却悬空；脚已落地身体仍无支撑漂移 |
| `trajectory_timing` 轨迹与时间 | 运动方向、高低、快慢是否与发力、重量感、着地姿态一致？ | 无原因的半空加速/悬停/折返；轻微屈腿却长时间垂直漂浮 |
| `normal_speed_readability` 正常速度理解 | 不看标签和骨架，能否自然读出这是什么动作、为何发生、怎样完成？ | 逐帧能解释，1×却像贴纸弹跳；必须靠文字说“蹬地”才看得出 |

`articulation` 同时检查骨段长度和角色体积稳定：不能靠不受控的腿段伸长制造蹬伸。明确设计的卡通形变可以保留，但画面须读得出形变原因与恢复；不设置通用百分比阈值。

每项分别写 `PASS / FAIL / UNREVIEWED` 和证据。不能以“看到了预备、腾空、落地三个状态”代替发力过程检查，也不能把没有发现问题当作完整通过。

## 最小工作量

1. **制作前，一张动作卡。** 写物种与动作意图、关键支撑部位、准备→施力/释放→运动→接触/承重→恢复的必要阶段、起止时码，以及夸张的部分。参考真实行为；物种不熟悉或幅度大时核一段真实影像或原始研究。不要把科学测量的固定角度、米数或时长生搬到卡通。
2. **作者做短样。** 只制作包含完整动作的短片。关键关节可以是少量点和连线；没有程序骨架也可用独立完整姿态或人工标点。可叠加骨架、接触标记和路径，但这些必须来自当前实际绘制对象或人工观察，不能另画一套“正确示意骨架”掩盖错误成片。
3. **独立审核先看干净成片1×。** 覆盖动作开始前、全动作和稳定结束；说出看到的发力和接触。再用0.5×或逐帧定位问题，并对照同一版本的接触/骨架辅助视图。首轮不先给“预期正确”的答案。
4. **程序只筛异常。** 可检查声明支撑区间的接触漂移、关节/轮廓突跳、事件先后与轨迹连续性。接触漂移以脚相对地面/枝条的同一坐标系测量，扣除镜头运动；镜头平移不是脚滑。骨架点需与实际像素叠加复核。容差按本镜尺寸、线宽和所选夸张方式记录。它不判断“自然”，不生成生物学合格证；作者自己的 telemetry 不是独立视觉审核。
5. **留证据再放行。** 绑定最终视频哈希、动作区间、作者/审核者身份、实际观看范围、各项结论和问题关闭记录。有 Important/Critical 或任一 `FAIL` 就 `REVISE`；缺关键记录为 `BLOCKED`；只有静帧/数值或未看完正常速度则 `PARTIAL`，不得作为动作验收通过交付。只有五项完整独立检查、实际1×全动作证据与问题关闭齐备才 `PASS`。

工具若只能抽帧，应明确说“完成抽帧筛查，正常速度可信度未验收”，并将门槛保持未通过；不能以等待播放结束、播放进度条、成功解码、FPS、截图数量或自己写的 `observed=true` 冒充看过。已知缺陷可以仅凭明确像素证据判失败，不必等待全片观看后才允许退回。

## 输出与机器检查

模板：[animal-motion-review.template.json](templates/animal-motion-review.template.json)。完成后运行：

```bash
python3 /absolute/path/to/swainwong-video-workflow/scripts/check_animal_motion_review.py /absolute/path/review.json
```

脚本校验文件哈希、身份独立性、五项证据及正常速度区间覆盖，输出 `PASS / REVISE / PARTIAL / BLOCKED`，非PASS退出码为1。它验证报告的完备性和自洽性，不能验证审核者是否诚实观看或是否具备判断力；责任仍属于署名审核者。审核报告的“声明PASS”不能覆盖脚本返回值。

用户指出漏检时：记录该用户反馈和原视频哈希，新增 superseding 报告，原报告保留。明确是哪项漏检、为何旧标准未拦住、以原片作为负例运行新检查。不能把旧失败写成只需“可选润色”，也不能悄悄改写旧结论。

## 本次反例

2026-10-26 花园兔子旧版：后腿姿态几乎保持坐姿，主体通过位移和整体缩放升空；虽然画面具备低→高→低与影子变化，但没有可读后腿蹬伸及落地承重。因此 `force_chain`、`articulation` 不通过。既有“有限动画”或“儿童卡通”的标签不能豁免；轻量修复应补清楚实际发力与收腿、落地缓冲，也可缩小动作幅度，但只降低高度不构成修复。
