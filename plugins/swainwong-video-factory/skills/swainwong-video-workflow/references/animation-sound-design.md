# 动画变化与声音反馈标准

适用于剪纸、表格、数据图形、文字卡片、连线、高亮及动效库动画。2026-10-27用户明确修正密度：**声音对应一个完整动作组，不对应每帧或组内每个状态；一次完整声音或一个短提示均可，禁止用短声堆积表示长运动。** 本版取代旧版“每步必响、连续动作必须全程发声”的要求，保留动画Agent对动效音效负责及声音分类、授权、对齐的职责。用户在本轮后续明确要求将这些最新要求整理写入工作流，故作为本skill的持续制作规范；具体片名、cue数量与音量实测值仍留项目，不作为跨片配额。

## 0. 动画 Agent 与 BGM Agent 分工

用户于2026-10-27明确职责：**⑥动画 Agent 对“画出来、动起来、配上对应动效音效”完整负责；⑫BGM Agent 独立负责跨镜头、段落及全片配乐。** 此分工适用于本工作流的动画制作、改编与返修；配乐不随动画片段的边界自动切断。

| 责任岗 | 负责的内容 | 交接产物 |
|---|---|---|
| ⑥动画与动效音效 | 视觉资产/构图、动作实现、按动作组声音角色分类、授权SFX选材、音色与包络、同步和动作声音返修 | 可编辑动画源码/工程、无BGM的动画＋SFX同步预览、独立可编辑SFX轨及素材、`animation_events`、`action_groups`与`sfx_cues`、来源/许可和实际视听状态 |
| ⑫BGM | 根据全片结构选择或制作音乐，处理跨镜接续、段落情绪、入出点、循环/交叉淡化和对人声/SFX的让位设计 | 独立可编辑BGM轨及素材、音乐使用表（来源/许可、全片时间码、增益/淡化、跨镜接续与让位区间）、试听状态 |
| ④口播音频 | 沿用已选声音，制作/整理口播并给出实测句子时码 | 口播轨、句子/时间映射和已批准音频身份 |
| ⑦剪辑合成 | 接收上述独立轨道，在全片时间线上组装与最终混音，检查接缝、重叠、旁白清晰度和导出 | 完整混音、保留独立轨的工程与返修时码；动作声音问题派回⑥，音乐问题派回⑫ |

主Agent分别派单给动画与BGM责任岗；两者是独立职责与产物，不让动画岗兼名BGM岗交付一条不可分混音。既有①–⑪编号保留，新增⑫BGM；岗位不要求同时运行，纯音频、局部返修或无BGM范围按适用性派单。

动画 Agent 执行已确认路径：**画面事件识别 → 动作分组 → 声音角色分类 → 授权素材库检索 → 对齐与试听混音**。按叙事作用、动作和材质选择声音：纸张运动、信息揭示、数据变化、关系延伸、机械接触和结论强调分别选合适声族；相同作用可沿用声音身份，不用同一声音或相近噪声换名覆盖所有类别。检索模型可辅助选候选，不能替代画面理解或真实听审，也不因写入流程就宣称模型已安装。

按声音的**作用**划分归属：直接响应动画事件的短音乐性提示/结论音仍属于⑥的SFX；跨镜头承载氛围、节奏与情绪的音乐归⑫，不按文件扩展名或“有旋律”判断。动画岗可以参照已确定的旁白/BGM节拍设计，并提交上下文混音预览，但须同时提供无BGM的同步预览和独立SFX，不能把音乐烧入动画素材或让每个动画各自重启BGM。

无声动画库只改变技术实现位置，不改变责任：⑥可在动画工程或目标编辑器的SFX轨上落地；需要⑦代为挂载时，⑥先交实际音频、准确时码及包络，并核对目标时间线最终确已带声。仅交无声画面、“后期再补音效”的文字或空cue表，均不能标动画交付完成。无法真实听审时可交待试听版本，明确缺口，不能签发视听PASS。动作、入点、缓动或时长变更由⑥同步修SFX；影响全片时长/音乐接续时通知⑫和⑦复核相关区间。

### 声音角色与表现力

| 角色 | 对应画面/叙事作用 | 候选声音方向（非固定素材） |
|---|---|---|
| 纸张/材质动作 | 剪纸展开、翻折、移动、接触 | 完整纸摩擦、展开或短纸触 |
| 信息揭示 | 标题、图标、证据卡出现 | 轻弹拨、柔和点声、提示音 |
| 数据变化 | 表格、柱线图、计数、数值结果 | 一次数据提示或平滑音高手势 |
| 关系建立 | 箭头、连线、划线、传导 | 单次笔触或连续滑音 |
| 机械接触 | 夹具打开、物件落位、书本合上 | 与物体匹配的一次开合/接触拟音 |
| 结论/反差 | 结果揭示、转折、叙事强调 | 简短强调音或音乐性短提示 |

这些是按作用选材的起点，同一组只选合适的一个声学重点，不要求把所有角色叠在一起。相同动作可保持声音身份；不同类别应能被听出作用差异，不能只改文件名或给同一噪声略调音高就声称已分类。综艺式配声应体现铺垫、反差、落点和材质选择，强弱服从本片语气与口播，不把连续搞笑音、重击或whoosh当成专业配置。

授权检索保留源地址、许可及实际使用片段；视觉/音频匹配库只辅助推荐。使用开源匹配库前另核代码和权重/素材各自许可、实际可运行性及本机限制，不能因仓库存在就宣称已安装或自动匹配成功。

## 1. 事件完整登记，声音按动作组设计

先核实际画面及动画代码，登记 `animation_events`，再按故事、对象、连续动作意图形成 `action_groups`，最后编排 `sfx_cues`。一次进入、展开、生长、位移、翻折或连续揭示可以包含多个视觉状态；渲染帧、补间、逐字、表格逐行和同一动画的关键帧不自动成为独立发声事件。

一个组选择以下一种声音方案：`one_shot`（开头、信息重点或结束处选一个锚点）或 `continuous_gesture`（一次完整声体）。已有合适声音可登记 `existing_sound`；原声保护或明确不适用登记 `exempt`。组内其他视觉事件标记 `grouped_no_retrigger` 并关联组及实际cue，属于有意设计，不算漏配。所有事件都须有处置，但不要求每项产生一个声音。

动作组不能只按时间机械聚类：同一镜头中不同故事、独立因果结果可以分组；同一动作跨镜、超过数秒仍可保持一组。不得把每行表格、每个补间状态重新命名为“新故事”逃避合并。不同音色、不同cue ID或不同对象若共同完成同一次揭示，也应评估合组。

普通字幕刷新、常驻Logo、导航条持续填充、史料内部自然运动和没有新增动画的硬切，默认不逐项配讲解动画SFX。保护原声时标明具体区间；不把保护扩大成整类动画静音。

## 2. 触发与防重复规则

1. **组内只触发一次。** 同一动作后续帧、状态与进度更新不重新触发；长动画不会因冷却时间到期再响。起、中、末选一个合适节点，不默认三个都配声。
2. **先看语义，再看间隔。** 独立故事或真正的新动作可分别发声；同故事密集揭示先合组。可用约2–3秒作为重复提示检查范围。已试项目采用2.5秒作为初始编辑值，后续项目按动作语义与试听调整，并非听觉科学阈值、全局强制间距或周期计时器。
3. **区分两个时间量。** 相邻候选起点间隔小于检查值，提示检查是否重复；同对象重新开始动作则核前一动作结束到新动作开始的空闲间隔，以及重新开始的画面证据。跨过检查值只允许重新评估，不自动生成新cue。不同故事在更短间隔发生可保留，各记独立边界与理由，并检查残响重叠。
4. **不要延迟排队补响。** 被组内去重的状态不会在冷却结束后补播。实时实现以动作组/播放实例为去重键；离线剪辑直接只落一条组级cue。不要在每次 `frame(t)` 调用里无条件播放声音。用户主动重播或新播放实例可重置，普通补帧不可重置。

同组一个短音可以代表数秒动作，不能因剩余时间无SFX就判失败。声音身份仍按材质和叙事角色分类：纸张、信息、数据、关系、机械接触、结论强调不应全部用同一种声音。

## 3. 声体选择：不靠短音拼成长音

| 画面 | 默认组级声音设计 | 不允许的做法 |
|---|---|---|
| 同一表格四五行在2秒内展开 | 整次展开选一次短提示，或一个完整展开声 | 每行一声，或把多个短声预混成一文件冒充“一声” |
| 柱形、折线、箭头延伸，连续计数 | 一次平滑的完整声体，或在开始/结果处选一个短音 | 用连续tick、click、短whoosh堆积填满运动时长 |
| 纸片或砖块从A移动到B、补间动画 | 一段完整运动声，或一个短起动/到位提示 | 每个关键帧重复触发、轮换短素材拼成长擦声 |
| 剪纸展开、翻折、缩放 | 一次真实连续纸张动作录音，或一个合适短纸触 | 采集微小响动颗粒并重复/交叉叠加来填满过程 |
| 多物体协调出现、逐字/墨迹/扫光 | 按一次共同揭示分组，选一个声学重点 | 每个对象或每字都单独触发 |
| 新故事、独立新动作、明确新结果 | 另组并选择对应声音；检查与前声是否抢注意 | 仅因时间到了而重复前声 |

`continuous_gesture`应来自一段真实连续素材，或一次相位/包络连续的合成手势；允许正常裁切、变速、均衡和首尾淡化。禁止循环、拼接或交叉叠加多个短瞬态来假装长音，换素材、改变音高或合并成一个WAV也不豁免。自然录音内部的合理材质变化不等于人为反复触发，但仍须听审；若实际听感仍是密集敲击，应另选完整素材或改用一个短提示。不得用响度覆盖率目标反向逼出填空声。

真实可见的多次独立碰撞/叙事节拍可另行设计声音，但必须记录为何是独立动作，不得以该例外给普通补帧或持续位移造脉冲组。声音不得暗示不存在的撞击或历史现场；编辑性Foley不能标为同期声。

## 4. 可重建交接

事件保留 `event_id / scene_id / object / change_type`、实际起止帧/秒、视觉锚点、画面证据、`group_id / disposition`。动作组记录 `group_id / story_id / object_or_ensemble / action_intent`、组边界、事件ID、`sound_strategy`、所选唯一发声锚点及理由、cue IDs、合并/不重触发原因、与相邻组的关系及任何短间隔例外。

每条cue记录文件、来源/许可、时间线入点、真实素材入出点、增益/包络、组ID、生成方式、导出哈希和审核状态。连续录音保留连续源区间；合成音保留可复建方法；不能只凭一个文件名宣称没有短音堆叠。已有声音覆盖须列实际资产/锚点；组级提示无需覆盖每一帧的声能。新旧音轨共同参与组级审计，检查已有FX、烘焙在素材内的声音与新增cue是否为同一次动作重复提示。核实际画面是否发生变化，不能仅凭旧文件名称或历史保留身份认定有动作；确无动作依据的残留装饰提示按当前返修范围移除或调整。保留原始资产，记录修改区间，防止同一声音同时从旧混音与独立轨播放。

⑥按第0节保留实际带声动画、独立可编辑SFX及无BGM同步预览；⑫单独交BGM，⑦汇总混音。登记实际 `native / override / unsupported` 能力；参考片混音不是干净SFX。动画节奏改变后重新核组边界和声音锚点。

## 5. 三层验收与返修

1. **分组与处置**：所有事件均有组级映射、已有覆盖或具体豁免；检查同动画是否被拆成连续短提示，是否有独立故事被错误合并。`grouped_no_retrigger`不算漏配，cue数量和全时声能覆盖不是目标。
2. **时间与制作证据**：核真实音轨、唯一组级触发、源区间/合成路径、同步锚点、保护窗和输出身份；检查素材内部是否仍是短效拼接或反复瞬态。一次短音代表长动作是允许方案，不要求补满声体；选完整长声时核它确为完整手势，而非用静音尾部冒充。
3. **正常速度看听**：检查一个动作是否听成反复提示、材质是否合适、是否抢旁白或误导动作、组间音尾是否冲突。单听SFX辅助定位，最终回到完整混音。抽帧、代码、波形、响度、文件数或播放成功不能代替实际听审；不能听时保留待核。

反复触发同一动画、短声拼长声、因计时器到点重响、无理由组级漏配、错位、明显抢话均应返修。不要以旧版“每步必响、过程缺声”再补回已合并的声音。

## 6. 调研依据与适用边界

- [Unreal Engine Sound Concurrency](https://dev.epicgames.com/documentation/en-us/unreal-engine/sound-concurrency-reference-guide)提供按声音组/对象限制播放及可配置Retrigger Time，支持组级去重机制；文档没有规定影视动画应使用2.5秒。
- [Apple Playing audio](https://developer.apple.com/design/human-interface-guidelines/playing-audio?changes=_8)建议处理长期重复声音的变化。音色变化只解决重复感的一部分，不替代用户要求的减少触发。

这些交互音频原则用于本流程的编辑设计推理，不是影视观众实验结论。2.5秒只作为已试项目的初始检查值，不是所有后续项目的强制默认；最终依据动作语义与真实试听调整，不能宣称已研究出普适最佳间隔。
